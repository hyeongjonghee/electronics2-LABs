0. 사전 결과 요약

LAB6은 10/26 수업(STM32_2 · 컴퓨터와 FPGA 통신)의 실습이다. FPGA 개별 실습 3개(서보모터 → SRAM → DAC)와 STM32 제공 예제 2개, 직접 작성 과제 3개(과제5 · 과제6 · 과제7)를 준비했다. 과제6·7에서 FPGA가 할 일(받은 문자 되돌려 보내기, 문자로 LED 제어)은 FPGA 회로 하나 uart_cmd_top으로 묶었다.

모든 FPGA 회로는 Icarus와 Vivado XSim 두 시뮬레이터에서 테스트벤치(TB)의 자동 검사를 통과했다. 수업 TB 외에, 실제 보드에서 문제가 될 만한 부분을 보려고 보드용 TB를 따로 만들었다. 서보는 버튼 떨림을 넣어 보고, SRAM·DAC는 데이터시트의 시간 조건을 넣은 칩 모델에 연결했다. 그 결과 수업 코드에서 보드 문제 3가지를 찾아 보드용 최상위에서 고쳤다(아래 경고 상자).

수업 코드에서 찾은 보드 문제 3가지 (LAB5 ADC처럼, 수업 FPGA 코드는 "보드 시연 미수행" 상태로 배포됨)
  1. 서보 · 타이밍 위반: servo_pwm의 폭 계산 pulse_us*(CLK_HZ/1000)/1000은 32비트 곱셈과 1000 나눗셈을 한 클록(20 ns) 안에 끝내야 한다. 50 MHz로 구현하면 WNS = −0.609 ns(20.6 ns가 필요). 1 µs가 정확히 50클록이므로 pulse_us × 50으로 바꾸어 WNS +12.86 ns, LUT 782 → 411.
  2. DAC · 쓰기 펄스 폭 여유 0: 쓰기 LOW 펄스가 1클록 = 20.0 ns인데 AD7302의 최소 폭도 20 ns다. 보드용은 2클록(40 ns, 여유 20 ns)으로 늘렸다.
  3. SRAM · 데이터 홀드 경쟁: 쓰기 버튼을 떼는 순간 WE가 HIGH가 되는 것과 FPGA가 데이터선을 놓는(Z) 것이 같은 순간이다. SRAM은 쓰기가 끝나는 에지에서 데이터를 저장하고 홀드 시간 조건은 0 ns라서, 여유가 전혀 없다. 지연 0 시뮬레이션에서는 17번 쓰기 모두 Z가 저장됐다(두 시뮬레이터 같음). 보드용은 50 MHz 클록으로 데이터를 WE 상승 뒤 2클록(40 ns) 더 유지한다 → 경쟁 0, 버스 충돌 0.
수업 TB는 이 셋을 잡지 못한다. 서보 TB는 100 kHz 느린 클록을 쓰고(타이밍과 무관), DAC TB는 펄스 폭이 "9 ns 이상"인지만 보며, SRAM TB의 모델은 쓰기가 시작할 때 저장한다(실제 칩은 끝날 때 저장).

1. 실험 1 · 서보모터 제어 (servo_ctrl)

① 목적

RC 서보모터는 20 ms마다 한 번 오는 펄스의 HIGH 길이로 각도를 정한다. 버튼(왼쪽 · 오른쪽)을 누를 때마다 펄스 폭을 0.1 ms씩 바꾸어 서보 각도가 단계적으로 움직이는 회로를 만들고, 폭이 1.0 ~ 2.0 ms 범위를 벗어나지 않는지 확인한다.

② 이론 · 설계 계산

서보 신호 읽는 법. 서보는 손목시계처럼 "20 ms마다 한 번" 오는 신호를 기다리고, 그 신호가 HIGH로 머문 시간을 잰다. 1.5 ms면 가운데, 1.0 ms와 2.0 ms면 양쪽 끝 쪽으로 돌아간다(정확한 각도는 서보 기종마다 다르다). 그래서 회로는 두 가지만 하면 된다. ① 20 ms 길이의 프레임을 계속 반복하고 ② 프레임 시작부터 원하는 폭만큼만 HIGH를 낸다.

$$N_{\text{frame}} = \frac{f_{clk}}{50} = \frac{50\,\text{MHz}}{50} = 1\,000\,000\ \text{클록}\ (20\ \text{ms}),\qquad N_{\text{width}} = t_{\mu s}\times\frac{f_{clk}}{10^6} = t_{\mu s}\times 50$$

모듈 구성. servo_position은 왼쪽 펄스에 −100 µs, 오른쪽 펄스에 +100 µs(1000 ~ 2000 사이에서만, 둘 다 들어오면 무시). servo_pwm은 0 ~ 999,999를 세는 카운터이고 count < width_cycles일 때 HIGH를 낸다. 새 폭은 프레임 경계에서만 반영해서, 펄스 도중 폭이 바뀌어 잘리는 일이 없다.

버튼 처리(보드용). left_pulse · right_pulse는 "버튼 한 번 = 한 클록 펄스"여야 한다. 손가락으로 누른 버튼은 수 ms 동안 접점이 떨려(바운스) 0/1을 여러 번 오가므로, 그대로 넣으면 한 번 눌러도 여러 칸 움직인다. 보드용 최상위 servo_board_top에 btn_onepulse를 넣었다: 2단 플립플롭 동기화 → 10 ms(500,000클록) 동안 같은 값이면 인정 → 0→1로 바뀌는 순간 한 클록 펄스.

타이밍 문제와 해결. 클록 한 칸(20 ns) 안에 끝나야 하는 계산이 너무 길면 FPGA가 제때 답을 못 낸다. 시험 시간 20분인데 25분짜리 문제를 낸 셈이다. 수업 식 pulse_us*(CLK_HZ/1000)/1000은 32비트 곱셈 뒤 1000 나눗셈이라 경로가 20.609 ns로 0.609 ns 늦었다(WNS = −0.609 ns). 50 MHz에서는 1 µs = 정확히 50클록이므로

$$\frac{t_{\mu s}\times 50\,000}{1000} = t_{\mu s}\times 50 = t_{\mu s}\times(32+16+2)$$

로 바꾸면 덧셈 세 번이면 된다. 보드용 servo_pwm_board는 클록이 1 MHz의 배수일 때만 이 식을 쓰고, TB의 느린 클록에서는 원래 식을 쓴다(generate). 1.0 ~ 2.0 ms의 11개 값 모두에서 두 식의 결과가 같음을 보드 TB에서 확인했다.

servo_position.v

`timescale 1ns/1ps
// 버튼은 동기화·디바운스 후 한 클록 길이의 펄스로 전달합니다.
module servo_position(
    input wire clk_50mhz,rst_p,left_pulse,right_pulse,
    output reg [31:0] pulse_us
);
    always @(posedge clk_50mhz)
        if(rst_p) pulse_us<=1500;
        else if(left_pulse && !right_pulse && pulse_us>1000) pulse_us<=pulse_us-100;
        else if(right_pulse && !left_pulse && pulse_us<2000) pulse_us<=pulse_us+100;
endmodule

servo_pwm.v (교재 · 타이밍 위반)

`timescale 1ns/1ps
module servo_pwm #(parameter CLK_HZ=50_000_000)(
    input wire clk_50mhz,rst_p,
    input wire [31:0] pulse_us,
    output wire servo
);
    localparam FRAME_CYCLES=CLK_HZ/50; // 20 ms
    reg [31:0] count;
    reg [31:0] width_cycles;
    always @(posedge clk_50mhz) begin
        if(rst_p) begin count<=0; width_cycles<=(CLK_HZ/1000)*3/2; end
        else if(count==FRAME_CYCLES-1) begin
            count<=0;
            // 프레임 경계에서만 폭을 바꿔 중간 펄스가 잘리지 않게 합니다.
            width_cycles<=pulse_us*(CLK_HZ/1000)/1000;
        end
        else count<=count+1;
    end
    assign servo=!rst_p && (count<width_cycles);
endmodule

servo_pwm_board.v (보드용 · ×50)

`timescale 1ns/1ps
// 보드용 servo_pwm. 수업 servo_pwm과 동작은 같고, 폭 계산식만 바꿨다.
// 수업식 pulse_us*(CLK_HZ/1000)/1000 은 32비트 곱셈 + 1000 나눗셈이 한 클록(20 ns) 안에 끝나야 해서
// 50 MHz 구현에서 WNS = -0.609 ns(타이밍 위반). CLK_HZ가 1 MHz의 배수이면 1 µs당 클록 수가 정수이므로
// pulse_us * (CLK_HZ/1_000_000) 한 번의 상수 곱(50 = 32+16+2, 덧셈 3개)으로 같은 값을 얻는다.
module servo_pwm_board #(parameter CLK_HZ=50_000_000)(
    input wire clk_50mhz,rst_p,
    input wire [31:0] pulse_us,
    output wire servo
);
    localparam FRAME_CYCLES=CLK_HZ/50; // 20 ms
    wire [31:0] width_next;
    generate
        if (CLK_HZ % 1_000_000 == 0) begin : g_exact
            assign width_next = pulse_us * (CLK_HZ/1_000_000);       // 보드(50 MHz): ×50
        end else begin : g_general
            assign width_next = pulse_us * (CLK_HZ/1000) / 1000;     // TB용 느린 클록(100 kHz 등)
        end
    endgenerate
    reg [31:0] count;
    reg [31:0] width_cycles;
    always @(posedge clk_50mhz) begin
        if(rst_p) begin count<=0; width_cycles<=(CLK_HZ/1000)*3/2; end
        else if(count==FRAME_CYCLES-1) begin
            count<=0;
            width_cycles<=width_next;       // 프레임 경계에서만 폭을 바꿔 중간 펄스가 잘리지 않게 한다
        end
        else count<=count+1;
    end
    assign servo=!rst_p && (count<width_cycles);
endmodule

btn_onepulse.v

`timescale 1ns/1ps
// 키패드 버튼(누르면 HIGH) -> 2단 동기화 -> 디바운스 -> 누를 때 한 클록 펄스.
// CNT 클록 동안 같은 값이 유지되어야 새 상태로 인정한다(50 MHz에서 500000 = 10 ms).
module btn_onepulse #(parameter integer CNT = 500_000)(
    input  wire clk, rst_p, btn,
    output reg  pulse
);
    (* ASYNC_REG = "TRUE" *) reg [1:0] sync;
    reg stable;
    reg [31:0] cnt;
    always @(posedge clk) begin
        if (rst_p) begin
            sync <= 2'b00; stable <= 1'b0; cnt <= 0; pulse <= 1'b0;
        end else begin
            sync  <= {sync[0], btn};
            pulse <= 1'b0;
            if (sync[1] == stable) cnt <= 0;              // 변화 없음: 카운터 비움
            else if (cnt == CNT-1) begin                   // 바뀐 값이 CNT 클록 유지됨
                cnt <= 0; stable <= sync[1];
                if (sync[1]) pulse <= 1'b1;                // 눌림(0->1)에서만 펄스
            end else cnt <= cnt + 1;
        end
    end
endmodule

// 보드 시연용 최상위: 키패드 버튼 -> btn_onepulse -> servo_position -> servo_pwm.
// 수업 servo_ctrl과 같은 두 모듈을 연결하고, 현재 위치(0~10)를 LED로 보여 준다.
module servo_board_top #(
    parameter integer CLK_HZ = 50_000_000,
    parameter integer DEBOUNCE_MS = 10
)(

    output wire servo,

2. 실험 2 · SRAM 읽기·쓰기 (sram)

① 목적

외부 SRAM 칩의 주소 0 ~ 15에 DIP 스위치로 정한 4비트 값을 쓰고, 같은 주소에서 다시 읽어 LED로 확인한다. FPGA와 SRAM이 같은 데이터선(16비트 양방향 버스)을 번갈아 쓰는 방법, 즉 쓸 때는 FPGA가 구동하고 읽을 때는 FPGA가 손을 떼는(Z) 방법을 익힌다.

② 이론 · 설계 계산

양방향 버스는 한 줄짜리 무전기. 데이터선 16개는 FPGA와 SRAM이 함께 쓴다. 둘이 동시에 말하면(둘 다 구동) 한쪽은 1, 다른 쪽은 0을 내서 전류가 흐르는 버스 충돌이 생긴다. 그래서 FPGA는 쓰기 때만 값을 내고, 그 밖에는 출력을 Z(고임피던스, 손 떼기)로 둔다: assign ram_data = drive_data ? {12'b0,data_in} : 16'bz;

제어 신호는 모두 LOW 활성(이름 끝 _n의 뜻). 수업 sram_bus_control은 순수 조합회로다.

쓰기는 "끝나는 순간"에 저장된다. 비동기 SRAM의 쓰기 구간은 CS · WE(· UB/LB)가 모두 LOW인 동안이고, 그중 하나가 먼저 HIGH가 되는 순간 데이터선의 값이 저장된다. 그래서 데이터는 그 순간 직전 \(t_{SD}\) 동안, 직후 \(t_{HD}\) 동안 그대로 있어야 한다(ISSI IS61WV25616 -10 등급).

sram_bus_control.v

`timescale 1ns/1ps
// SRAM 버스는 읽을 때 FPGA가 구동하지 않고 Z 상태로 놓습니다.
// ctrl_w와 ctrl_r가 동시에 들어오면 둘 다 수행하지 않습니다.
module sram_bus_control(
    input wire ctrl_w,ctrl_r,
    output wire drive_data,read_data,
    output wire ram_cs,ram_oe,ram_we
);
    assign drive_data=ctrl_w && !ctrl_r;
    assign read_data=ctrl_r && !ctrl_w;
    assign ram_cs=!(drive_data || read_data);
    assign ram_oe=!read_data;
    assign ram_we=!drive_data;
endmodule

sram_board_top.v (보드용 최상위)

`timescale 1ns/1ps
// 보드 시연용 SRAM 최상위.
// 수업 sram은 조합회로라서 쓰기 버튼을 떼는 순간 WE 상승과 데이터 버스 해제(Z)가 동시에 일어난다
// -> SRAM 데이터 홀드 tHD = 0 ns 조건과 여유 0의 경쟁. 여기서는 50 MHz 클록으로
//   (1) 버튼을 2단 동기화하고, (2) 쓰기가 끝난 뒤 데이터를 HOLD_CYCLES 클록 더 구동한 다음 Z로 놓는다.
// 동시 요청 무시, 미사용 시 Z, LED 표시는 수업 sram과 같다. UB/LB(바이트 선택, LOW 활성)는 LOW 고정.
module sram_board_top #(parameter integer HOLD_CYCLES = 2)(
    input  wire clk_50mhz,
    input  wire ctrl_w, ctrl_r,
    input  wire [3:0] address, data_in,
    output wire ram_cs, ram_oe, ram_we,
    output wire ram_ub, ram_lb,
    output wire [17:0] ram_address,
    inout  wire [15:0] ram_data,
    output wire [7:0] led_out
);
    (* ASYNC_REG = "TRUE" *) reg [1:0] w_sync = 2'b00, r_sync = 2'b00;
    reg [3:0] hold = 0;
    always @(posedge clk_50mhz) begin
        w_sync <= {w_sync[0], ctrl_w};
        r_sync <= {r_sync[0], ctrl_r};
    end
    wire drive_req, read_req, cs_unused, oe_unused, we_unused;
    // 수업 버스 제어 모듈을 동기화된 버튼으로 그대로 사용(동시 요청 무시 규칙 유지)
    sram_bus_control u_control(w_sync[1], r_sync[1], drive_req, read_req, cs_unused, oe_unused, we_unused);
    always @(posedge clk_50mhz)
        if (drive_req) hold <= HOLD_CYCLES;
        else if (hold != 0) hold <= hold - 1'b1;
    wire drive_data = drive_req || (hold != 0);          // 쓰기 끝난 뒤에도 데이터 유지
    wire read_data  = read_req && (hold == 0);           // 데이터 해제 후에만 읽기
    assign ram_we = !drive_req;
    assign ram_oe = !read_data;
    assign ram_cs = !(drive_data || read_data);
    assign ram_ub = 1'b0;
    assign ram_lb = 1'b0;
    assign ram_address = {14'b0, address};
    assign ram_data = drive_data ? {12'b0, data_in} : 16'bz;
    assign led_out = read_data ? {4'b0, ram_data[3:0]} : 8'b0;
endmodule

async_sram_model.sv (보드 TB용 SRAM 모델 · ISSI -10 등급 시간 조건)

`timescale 1ns/1ps
// 256K x 16 비동기 SRAM 모델(10 ns급, IS61WV25616 계열 대표값). 읽기 경로 지연과 쓰기 타이밍 검사를 넣었다.
//  tAA 10 / tDOE 4.5 / tHZOE 4 (읽기),  tWP 8 / tSD 6 / tHD 0 / tSA 0 / tHA 0 (쓰기)
module async_sram_model(
    input wire ce_n, oe_n, we_n, ub_n, lb_n,
    input wire [17:0] a,
    inout wire [15:0] dq
);
    reg [15:0] mem [0:15];
    reg [15:0] dout; reg drive = 0;
    realtime t_we_fall = 0, t_addr = 0, t_dq = 0;
    integer violations = 0, writes = 0, contention = 0, hold_races = 0;
    wire read_en = !ce_n && !oe_n && we_n;
    // 쓰기 구간 = CE와 WE가 모두 LOW인 동안. 둘 중 먼저 HIGH가 되는 순간 데이터를 저장한다(데이터시트 정의).
    wire wr_active = !ce_n && !we_n;
    assign dq = drive ? dout : 16'bz;
    always @(a)  begin
        t_addr = $realtime;
        if (wr_active) begin violations = violations + 1; $display("%t SRAM violation: address changed during write", $realtime); end
    end
    always @(dq) t_dq = $realtime;
    always @(read_en or a) begin
        if (read_en) begin #4.5; if (read_en) begin dout = 16'bx; drive = 1; #5.5; dout = mem[a[3:0]]; end end
        else begin #4; drive = 0; end
    end
    reg armed = 0;   // 시작 순간 X->0 같은 초기 에지는 쓰기로 세지 않는다(실제 0->1->0 구간만)
    always @(posedge wr_active) if (wr_active === 1'b1) begin t_we_fall = $realtime; armed = 1; end
    always @(negedge wr_active) if (armed && wr_active === 1'b0) begin
        armed = 0;
        if ($realtime - t_we_fall < 8.0) begin violations = violations + 1; $display("%t SRAM violation: tWP", $realtime); end
        if (^dq === 1'bx) begin                         // 쓰기 끝과 같은 순간 버스가 Z/X -> tHD=0 경쟁
            hold_races = hold_races + 1;
        end else if ($realtime - t_dq < 6.0) begin violations = violations + 1; $display("%t SRAM violation: tSD", $realtime); end
        if (ub_n !== 1'b0 || lb_n !== 1'b0) begin violations = violations + 1; $display("%t SRAM violation: byte enable high", $realtime); end
        mem[a[3:0]] = dq; writes = writes + 1;
    end
    // 충돌 검사: SRAM이 확정된 값을 내보내는 중인데 버스 값이 다르면 FPGA도 구동 중인 것(충돌).
    always @(dq or drive or dout) #0.1 if (drive && (^dout !== 1'bx) && dq !== dout) begin
        contention = contention + 1; $display("%t SRAM bus contention dq=%h dout=%h", $realtime, dq, dout); end
endmodule

3. 실험 3 · DAC (dac)

① 목적

8비트 병렬 DAC 칩에 0, 1, 2, …, 255, 0, …을 차례로 써서 계단 모양 톱니파를 만들고, 오실로스코프로 디지털 값에 따라 아날로그 전압이 달라지는 것을 확인한다. 데이터를 먼저 놓고 쓰기 펄스로 "저장"하는 병렬 버스 쓰기 순서와, 칩 데이터시트의 시간 조건을 지키는 법을 익힌다.

② 이론 · 설계 계산

DAC는 숫자를 전압으로 바꾸는 계량컵. 8비트 값 \(D\)를 주면 기준 전압 \(V_{ref}\)를 256칸으로 나눈 것 중 \(D\)칸만큼의 전압을 낸다.

$$V_{out} = V_{ref}\cdot\frac{D}{256},\qquad \Delta V = \frac{V_{ref}}{256}$$

예를 들어 \(V_{ref}=2.5\ \text{V}\)이면 한 칸은 9.77 mV이고, \(D=255\)일 때 2.490 V가 최대다.

값을 바꾸는 속도. ramp8은 50 MHz에서 500,000클록마다(10 ms) 값을 1 올린다. 256칸을 다 오르는 데

$$T_{ramp} = 256 \times \frac{500\,000}{50\,\text{MHz}} = 256 \times 10\ \text{ms} = 2.56\ \text{s}\quad(f = 0.39\ \text{Hz})$$

가 걸린다. 오실로스코프에서는 500 ms/칸 정도로 봐야 톱니 한 주기가 보이고, 칸(9.8 mV 계단)은 확대해야 보인다. 실제 \(V_{ref}\)는 교재 회로도로 확인한다(보드 TB 모델은 2.5 V로 가정).

쓰기 순서. dac_parallel8은 update 클록에 데이터 · A/B 채널을 레지스터에 넣고 같은 클록에 WR을 LOW로 만든 뒤, 다음 클록에 WR을 HIGH로 되돌린다. CS와 LDAC는 항상 LOW이므로, 칩은 WR이 올라가는 순간 값을 받아 바로 출력을 바꾼다(LDAC LOW = 즉시 갱신).

ramp8.v

`timescale 1ns/1ps
module ramp8 #(parameter UPDATE_CYCLES=500_000)(
    input wire clk_50mhz,rst_p,
    output reg [7:0] value,
    output wire update
);
    reg [31:0] count;
    assign update=(count==UPDATE_CYCLES-1);
    always @(posedge clk_50mhz) begin
        if(rst_p) begin count<=0; value<=0; end
        else if(update) begin count<=0; value<=value+1'b1; end
        else count<=count+1;
    end
endmodule

dac_parallel8.v (교재)

`timescale 1ns/1ps
// 데이터는 쓰기 LOW 펄스 전에 등록하고, 펄스 종료까지 유지합니다.
module dac_parallel8(
    input wire clk_50mhz,rst_p,update,channel,
    input wire [7:0] value,
    output wire cs_n,ldac_n,
    output reg we_n,a_b,
    output reg [7:0] data
);
    assign cs_n=0;
    assign ldac_n=0;
    always @(posedge clk_50mhz) begin
        if(rst_p) begin we_n<=1; a_b<=0; data<=0; end
        else begin
            we_n<=1;
            if(update) begin data<=value; a_b<=channel; we_n<=0; end
        end
    end
endmodule

dac_board_top.v (보드용 · WR 2클록)

`timescale 1ns/1ps
// 보드 시연용 DAC 최상위. 수업 dac와 같은 ramp8을 쓰되, 쓰기 LOW 폭을 WR_CYCLES 클록으로 늘린다.
// AD7302 계열 병렬 DAC의 WR 최소 폭은 20 ns -> 50 MHz 1클록(20 ns)은 여유 0이므로 2클록(40 ns) 사용.
module dac_board_top #(
    parameter integer UPDATE_CYCLES = 500_000,
    parameter integer WR_CYCLES = 2
)(
    input  wire clk_50mhz, rst_p, add_sel,
    output wire dac_csn, dac_ldacn,
    output reg  dac_wen, dac_a_b,
    output reg  [7:0] dac_d,
    output wire [7:0] led_out
);
    wire [7:0] value;
    wire update;
    reg  [3:0] wr_left;
    ramp8 #(.UPDATE_CYCLES(UPDATE_CYCLES)) u_ramp(clk_50mhz, rst_p, value, update);
    assign dac_csn = 1'b0;          // 칩 선택 상시
    assign dac_ldacn = 1'b0;        // LDAC LOW: WR 상승 에지에서 바로 출력 갱신
    always @(posedge clk_50mhz) begin
        if (rst_p) begin dac_wen <= 1'b1; dac_a_b <= 1'b0; dac_d <= 8'd0; wr_left <= 0; end
        else if (update) begin
            dac_d <= value; dac_a_b <= add_sel; dac_wen <= 1'b0; wr_left <= WR_CYCLES-1;
        end else if (wr_left != 0) wr_left <= wr_left - 1'b1;
        else dac_wen <= 1'b1;
    end
    assign led_out = dac_d;
endmodule

ad7302_model.sv (보드 TB용 DAC 모델)

`timescale 1ns/1ps
// AD7302(이중 8비트 병렬 DAC) 디지털 인터페이스 + 출력 모델.
// 데이터시트 B등급(VDD 2.7~5.5 V) 최소값: t5 WR 폭 20 ns, t6 데이터 셋업 15 ns, t7 데이터 홀드 4.5 ns,
// t1/t2 A/B 셋업·홀드 0 ns, t3/t4 CS 셋업·홀드 0 ns. LDAC LOW이면 WR 상승 에지에서 DAC 레지스터 갱신.
module ad7302_model #(parameter real VREF = 2.5)(
    input wire cs_n, wr_n, ldac_n, a_b,
    input wire [7:0] d
);
    real vout_a = 0.0, vout_b = 0.0;
    realtime t_wr_fall = 0, t_d_change = 0, t_ab_change = 0, t_wr_rise = -1000;
    realtime min_wr = 1e9, min_su = 1e9, min_hold = 1e9;
    integer writes = 0, violations = 0;
    reg armed = 0;   // X->1 같은 리셋 초기 에지는 쓰기로 세지 않는다
    always @(d)   begin
        t_d_change = $realtime;
        if ($realtime - t_wr_rise < 4.5 && writes > 0 && $realtime > t_wr_rise) begin
            violations = violations + 1; $display("%t AD7302 data hold violation", $realtime); end
        if ($realtime - t_wr_rise < min_hold && writes > 0) min_hold = $realtime - t_wr_rise;
    end
    always @(a_b) t_ab_change = $realtime;
    always @(negedge wr_n) if (wr_n === 1'b0) begin
        t_wr_fall = $realtime; armed = 1;
        if (cs_n !== 1'b0) begin violations = violations + 1; $display("%t AD7302 CS not low at WR fall", $realtime); end
    end
    always @(posedge wr_n) if (cs_n === 1'b0 && armed && wr_n === 1'b1) begin
        armed = 0;
        t_wr_rise = $realtime;
        if ($realtime - t_wr_fall < min_wr) min_wr = $realtime - t_wr_fall;
        if ($realtime - t_d_change < min_su) min_su = $realtime - t_d_change;
        if ($realtime - t_wr_fall < 20.0) begin violations = violations + 1; $display("%t AD7302 WR pulse %0.1f ns < 20", $realtime, $realtime - t_wr_fall); end
        if ($realtime - t_d_change < 15.0) begin violations = violations + 1; $display("%t AD7302 data setup %0.1f ns < 15", $realtime, $realtime - t_d_change); end
        if (ldac_n === 1'b0) begin
            if (a_b) vout_b = VREF * d / 256.0; else vout_a = VREF * d / 256.0;
        end
        writes = writes + 1;
    end
endmodule

4. 실험 4 · STM32_2 제공 예제 2개

① 목적

① PC의 Serial Monitor에서 보낸 문자를 MCU가 getchar()로 받아 그대로 다시 출력하고, ② 받은 한 바이트를 UART3(PC10)로 FPGA에 보내 그 결과값(HAL_OK = 0)을 출력한다. 이후 과제 5 ~ 7의 바탕이 된다.

② 이론 · 설계 계산

getchar는 기다린다. getchar() → _read() → __io_getchar() → HAL_UART_Receive(&huart2, &byte, 1, HAL_MAX_DELAY)로 이어진다. 문자가 올 때까지 이 함수 안에서 계속 기다리므로, 입력이 없을 때 화면이 조용한 것은 멈춘(고장) 것이 아니라 기다리는 중이다. 결과를 int에 받는 이유는 0 ~ 255 문자 말고도 오류 표시 EOF(−1)를 구분해야 하기 때문이다.

자료형. UART_HandleTypeDef는 UART 설정·상태를 묶은 구조체이고 huart3은 그 변수다(ece2_474.h에 extern 선언). HAL_StatusTypeDef는 결과를 나타내는 enum: HAL_OK = 0, HAL_ERROR = 1, HAL_BUSY = 2, HAL_TIMEOUT = 3. HAL_UART_Transmit(&huart3, &data, 1U, 100U)은 "huart3 장치로, data가 있는 주소에서, 1바이트를, 최대 100 ms 기다리며 보내라"는 뜻이다.

전송 결과 0의 의미. HAL_OK는 "MCU가 마지막 비트까지 내보냈다"는 뜻일 뿐, FPGA가 받았다는 뜻이 아니다(UART는 받는 쪽의 응답이 없다). 받았는지는 FPGA 출력으로 따로 확인해야 한다(과제6).

5. 실험 5 · STM32_2 과제5 — PC → MCU → PC

① 목적

PC에서 보낸 문자 한 개를 MCU가 받아 문자와 그 바이트 값(16진수)을 함께 출력한다. 문자 1 · A · a가 0x31 · 0x41 · 0x61로 나오는지 확인한다.

② 이론 · 설계 계산

문자도 결국 숫자. 키보드의 글자는 ASCII 표에 따라 한 바이트 숫자로 바뀌어 전송된다. 숫자 글자 '0' ~ '9'는 0x30 ~ 0x39, 대문자는 0x41부터, 소문자는 대문자 + 0x20이다. 그래서 글자 '1'(0x31)과 숫자 1(0x01)은 완전히 다른 값이다.

문자'0''1''2''A''a'CR (\r)LF (\n)숫자 1
16진수0x300x310x320x410x610x0D0x0A0x01
10진수484950659713101

출력 형식. printf("0x%02X", data)의 %02X는 "16진수 대문자, 두 자리, 빈 자리는 0"이다. 화면에 찍히지 않는 제어 문자(0x20 미만, 0x7F 이상)는 글자 대신 "(제어 문자)"와 값만 출력한다. Serial Monitor의 줄바꿈 설정이 "CR+LF"이면 문자 뒤에 0x0D · 0x0A가 따라오는 것이 그대로 보여서, 매뉴얼이 줄바꿈을 없음(None)으로 하라는 이유를 확인할 수 있다.

③ 포트 · 보드 매핑

6. 실험 6 · STM32_2 과제6 — PC → MCU → FPGA → PC

① 목적

MCU가 PC에서 받은 한 바이트를 UART3(PC10)로 FPGA에 넘기고, FPGA는 받은 문자를 자기 USB-UART(F6)로 PC에 다시 내보낸다. PC에 생기는 두 COM 포트(MCU VCP, FPGA USB-UART)를 함께 열어 보낸 문자와 FPGA가 받은 문자가 같은지 비교한다.

② 이론 · 설계 계산

UART 한 글자 = 10칸 기차. 선이 쉬는 동안은 HIGH. 보낼 때는 시작 비트(LOW) 1칸 → 데이터 8칸(낮은 비트부터) → 정지 비트(HIGH) 1칸이다. 9600 bps면 한 칸이

$$t_{bit} = \frac{1}{9600} = 104.17\ \mu\text{s},\qquad t_{byte} = 10\,t_{bit} = 1.042\ \text{ms}$$

이다. 시계선이 따로 없으므로, 받는 쪽은 자기 시계로 시작 비트의 하강 에지부터 시간을 재어 각 칸의 한가운데에서 값을 읽는다. FPGA(50 MHz)에서 한 칸의 클록 수는

$$DIV = \operatorname{round}\!\left(\frac{50\,000\,000}{9600}\right) = 5208,\qquad f_{\text{실제}} = \frac{50\,\text{MHz}}{5208} = 9600.6\ \text{bps}$$

(오차 0.006 %)이고, 수신기는 하강 에지 뒤 \(DIV/2\)에서 시작 비트를 다시 확인한 다음 \(DIV\)마다 8번 읽는다. 10칸 동안 쌓이는 어긋남이 반 칸(5 %)보다 작으면 되므로 0.006 %는 충분하다.

FPGA 회로 uart_cmd_top. LAB3-07 UART 에코 회로(uart.v의 uart_rx · uart_tx)를 그대로 쓰고, ① 수신 입력을 보드 USB-UART(C6) 대신 확장 GPIO 핀 mcu_rxd로 바꾸고, ② 송신기가 바쁠 때 다음 바이트가 오면 한 개를 보관했다가 보내도록 했다. 받은 바이트는 그대로 F6로 다시 나간다.

/* STM32_2_과제6: PC -> MCU -> FPGA -> PC
 * PC에서 받은 한 바이트를 UART3(PC10, 9600 8N1)로 FPGA에 그대로 전달합니다.
 * FPGA는 받은 문자를 자기 USB-UART로 PC에 다시 내보냅니다(두 COM 포트 비교).
 */
void polling_routine(void)
{
    int ch = getchar();

    {
        uint8_t data = (uint8_t)ch;
        /* 1바이트 송신, 최대 100 ms 대기. 결과 0(HAL_OK)은 "MCU가 다 보냈다"는 뜻일 뿐,

        HAL_StatusTypeDef result = HAL_UART_Transmit(&huart3, &data, 1U, 100U);

        else

FPGA · uart_cmd_top.v (과제6·7 공용)

`timescale 1ns/1ps
// LAB6 과제6·7 공용 FPGA 회로 (LAB3-07 UART 에코 회로 확장)
//  - mcu_rxd : MCU PC10(UART3 TX)에서 오는 직렬 입력. 확장 GPIO(BDIO) 핀으로 받는다.  ← LAB3의 C6에서 변경
//  - uart_txd: 받은 바이트를 그대로 보드 USB-UART(F6)로 PC에 출력 (과제6)
//  - led[7] = LED1: '0' 끄기, '1' 켜기, '2' 반전, 그 밖은 유지 (과제7)
//  - led[6:0] = LED2~8: 마지막으로 받은 바이트의 하위 7비트 ('1'=0x31 -> 011_0001, 숫자 1=0x01 -> 000_0001)
module uart_cmd_top #(
    parameter integer CLK_HZ = 50_000_000,
    parameter integer BAUD   = 9_600
)(
    input  wire clk_50mhz,
    input  wire rst_p,
    input  wire mcu_rxd,
    output wire uart_txd,
    output wire [7:0] led
);
    localparam integer DIV = (CLK_HZ + BAUD/2) / BAUD;   // 50 MHz / 9600 = 5208 클록/비트
    wire [7:0] rx_data; wire rx_valid, rx_framing_error;
    wire tx_ready;
    reg  tx_valid; reg [7:0] tx_data;
    reg  pending; reg [7:0] pending_data;                 // 송신 중에 다음 바이트가 오면 한 개 보관
    reg  lamp; reg [7:0] last_data;

    uart_rx #(.DIV(DIV)) u_rx(.clk(clk_50mhz), .rst_p(rst_p), .rx(mcu_rxd),
                              .data(rx_data), .valid(rx_valid), .framing_error(rx_framing_error));
    uart_tx #(.DIV(DIV)) u_tx(.clk(clk_50mhz), .rst_p(rst_p), .valid(tx_valid), .data(tx_data),
                              .ready(tx_ready), .tx(uart_txd));

    always @(posedge clk_50mhz) begin
        if (rst_p) begin
            tx_valid <= 0; tx_data <= 0; pending <= 0; pending_data <= 0;
            lamp <= 0; last_data <= 0;
        end else begin
            tx_valid <= 0;
            // 과제7: 명령 해석 (문자 '0'=0x30, '1'=0x31, '2'=0x32)
            if (rx_valid) begin
                last_data <= rx_data;
                case (rx_data)
                    8'h30:   lamp <= 1'b0;
                    8'h31:   lamp <= 1'b1;
                    8'h32:   lamp <= ~lamp;
                    default: lamp <= lamp;
                endcase
            end
            // 과제6: 에코. 송신기가 비어 있으면 바로, 바쁘면 한 바이트 보관 후 전송
            if (rx_valid && !pending && !(tx_ready && !tx_valid)) begin
                pending <= 1; pending_data <= rx_data;
            end
            if (tx_ready && !tx_valid) begin
                if (pending) begin tx_data <= pending_data; tx_valid <= 1; pending <= rx_valid; pending_data <= rx_data; end
                else if (rx_valid) begin tx_data <= rx_data; tx_valid <= 1; end
            end
        end
    end
    assign led = {lamp, last_data[6:0]};
endmodule

FPGA · uart.v (LAB3-07 그대로)

`timescale 1ns/1ps
module uart_rx #(parameter integer DIV = 5208)(
    input wire clk, rst_p, rx,
    output reg [7:0] data,
    output reg valid,
    output reg framing_error
);
    (* ASYNC_REG="TRUE" *) reg [1:0] sync;
    reg [1:0] state;
    integer timer;
    reg [2:0] bitno;
    reg [7:0] shift;
    always @(posedge clk) begin
        if (rst_p) begin
            sync<=3; state<=0; timer<=0; bitno<=0; shift<=0;
            data<=0; valid<=0; framing_error<=0;
        end else begin
            sync<={sync[0],rx}; valid<=0; framing_error<=0;
            case(state)
                0: if(!sync[1]) begin timer<=DIV/2-1; state<=1; end
                1: if(timer!=0) timer<=timer-1;
                    else if(sync[1]) state<=0;
                    else begin timer<=DIV-1; bitno<=0; state<=2; end
                2: if(timer!=0) timer<=timer-1;
                    else begin
                        shift[bitno]<=sync[1]; timer<=DIV-1;
                        if(bitno==7) state<=3; else bitno<=bitno+1'b1;
                    end
                3: if(timer!=0) timer<=timer-1;
                    else begin
                        if(sync[1]) begin data<=shift; valid<=1; end
                        else framing_error<=1;
                        state<=0;
                    end
            endcase
      end
    end
endmodule

module uart_tx #(parameter integer DIV = 5208)(
    input wire clk, rst_p, valid,
    input wire [7:0] data,
    output wire ready,
    output wire tx
);
    reg [9:0] shift;
    reg [3:0] remaining;
    integer timer;
    assign ready = (remaining == 0);
    assign tx = ready ? 1'b1 : shift[0];
    always @(posedge clk) begin
        if(rst_p) begin shift<=10'h3ff; remaining<=0; timer<=0; end
        else if(ready) begin
            if(valid) begin shift<={1'b1,data,1'b0}; remaining<=10; timer<=DIV-1; end
        end else if(timer!=0) timer<=timer-1;
        else begin timer<=DIV-1; shift<={1'b1,shift[9:1]}; remaining<=remaining-1'b1; end
    end
endmodule

7. 실험 7 · STM32_2 과제7 — UART 명령으로 FPGA LED 제어

① 목적

FPGA가 받은 문자를 명령으로 해석해 LED를 제어한다: 0 끄기, 1 켜기, 2 반전, 그 밖의 문자는 유지. 특히 1을 반복하면 계속 켜져 있고, 2를 반복하면 매번 바뀌는지 확인하고, 글자 '1'(0x31)과 숫자 1(0x01)을 구분한다.

② 이론 · 설계 계산

"켜기"와 "반전"의 차이. 켜기는 지금 상태와 상관없이 1로 정하는 것이고(전등 스위치를 "켜짐" 쪽으로 미는 것), 반전은 지금 상태를 뒤집는 것이다(누를 때마다 바뀌는 버튼식 스위치). 그래서 상태를 기억하는 플립플롭 lamp 하나와, 받은 바이트로 다음 상태를 고르는 case문이면 된다.

$$lamp_{next} = \begin{cases}0 & rx = \text{0x30 ('0')}\\ 1 & rx = \text{0x31 ('1')}\\ \overline{lamp} & rx = \text{0x32 ('2')}\\ lamp & \text{그 밖 (0x01, 'x' 등)}\end{cases}\qquad(\text{rx_valid}=1\text{인 클록에만})$$

LED 배치. LED1(led[7]) = 명령으로 제어하는 램프, LED2 ~ 8(led[6:0]) = 마지막으로 받은 바이트의 아래 7비트. 글자 '1'은 011 0001, 숫자 1은 000 0001로 켜져서 둘의 차이가 눈으로 보인다. MCU 쪽은 과제6과 같은 전달 코드에 어떤 명령인지 이름만 함께 출력한다(판단은 FPGA가 한다).

과제6과 같은 회로·핀·비트스트림(LAB6-04_uart_cmd.bit)을 쓴다. LED1 = L4, LED2~8 = M4 M2 N7 M7 M3 M1 N5.

고찰

  1. "TB PASS"와 "보드에서 동작"은 다르다. 세 FPGA 실습 모두 수업 TB를 통과했지만, 보드 조건을 넣자 서보는 타이밍 위반(−0.609 ns), DAC는 쓰기 폭 여유 0, SRAM은 데이터 홀드 경쟁이 드러났다. 공통 원인은 TB가 확인하는 것과 보드가 요구하는 것의 차이다. 느린 클록(서보), 축소된 기준값(DAC 9 ns), 실제와 다른 저장 시점(SRAM 모델)이다. LAB5 ADC에서 배운 대로 외부 칩은 데이터시트 숫자를 모델에 넣어 검사했고, 그래서 실험 전에 고칠 수 있었다.
  2. 두 시뮬레이터를 쓰는 이유. 측정 숫자는 Icarus와 XSim이 모두 같았지만, XSim은 Icarus가 넘어간 두 가지를 잡았다. ① 선언하기 전에 쓴 신호(wr_active) ② 시간 0에 X → 0으로 정해지는 에지를 모델이 "쓰기 끝"으로 센 것. 둘 다 회로가 아니라 내가 쓴 TB 모델의 실수였다. 시뮬레이터 하나만 쓰면 그 도구의 너그러움에 기대게 된다.
  3. "같은 순간"은 설계가 아니다. SRAM 경쟁은 지연 0 시뮬레이션에서 처리 순서로 결과가 갈린다. 보드에서는 나노초 단위의 핀 지연이 같은 역할을 한다. 순서가 결과를 바꾸는 곳에는 클록으로 명확한 간격(여기서는 40 ns)을 두는 것이 안전하다.
  4. 곱셈·나눗셈 한 줄의 값. 서보의 /1000은 LAB5 피아노의 변수 나눗셈처럼 큰 회로가 됐고, 이번에는 타이밍까지 어겼다. 단위를 "µs당 클록 수"로 바꿔 생각하니 상수 곱 하나로 끝났다(LUT 782 → 411, 여유 +12.86 ns).
  5. UART에는 확인 응답이 없다. MCU의 전송 결과 0은 보내기를 마쳤다는 뜻일 뿐이다. 과제6에서 FPGA가 받은 값을 다른 COM 포트로 돌려보내게 한 것은, 받는 쪽의 결과로만 통신 성공을 판단할 수 있기 때문이다. 또 문자 '1'(0x31)과 숫자 1(0x01)이 다르다는 점을 LED2~8로 직접 보이게 했다.
  6. getchar 방식의 한계. 메인 루프가 getchar에서 기다리는 동안 다른 일을 못 하고, printf(9600 bps에서 40글자 ≈ 42 ms) 중에 다음 문자가 오면 놓칠 수 있다. 그래서 당일에는 문자를 하나씩 보낸다(talk6는 0.3 s 간격). 계속 받아야 한다면 UART 인터럽트 수신(HAL_UART_Receive_IT)이 맞다.
  7. 모델의 한계. SRAM · DAC 모델은 데이터시트의 디지털 시간 조건만 담았다. 보드 배선 지연, DAC 출력의 정착 시간과 잡음, 서보의 실제 각도는 실험 후 보고서에서 오실로스코프와 영상으로 비교한다.
