1. 실험 1 · 4비트 곱셈기 (mult_4bit)

① 목적

4비트 수 두 개를 곱해 8비트 결과를 내는 조합회로를 만들고, 256개 입력 조합 전체에서 결과가 맞는지 확인한다. 보드에서는 스위치로 두 수를 넣고 LED 8개로 곱을 읽는다.

② 이론 · 설계 계산

결과가 왜 8비트면 충분한가. 4비트 부호 없는 수는 0~15이다. 가장 큰 곱은

$$P_{\max} = 15 \times 15 = 225 \;<\; 2^8 = 256$$

이므로 8비트(0~255)에 항상 들어간다. 일반적으로 \(n\)비트 × \(n\)비트 곱은 \(2n\)비트면 넘치지 않는다. \((2^n-1)^2 < 2^{2n}\)이기 때문이다.

하드웨어가 곱하는 방법. 초등학교 세로 곱셈과 같다. \(B\)의 각 자리 비트 \(b_i\)가 1이면 \(A\)를 \(i\)칸 왼쪽으로 민 값(부분곱)을 더한다 [1].

$$P = A \cdot B = \sum_{i=0}^{3} b_i \,\bigl(A \cdot 2^{i}\bigr)$$

예를 들어 \(5 \times 3\)은 \(B=0011\)이므로 \(5\cdot 2^0 + 5\cdot 2^1 = 5 + 10 = 15\)이다. 이진수로는 \(0101 + 1010 = 0000\,1111\)이다.

RTL은 assign product = a * b; 한 줄이다. 곱셈 기호를 쓰면 합성 도구가 부분곱과 덧셈 회로를 대신 만든다. 이 회로는 크기가 작아서 Vivado가 DSP 블록 대신 LUT 16개로 구현했다(⑥ 참고).

2. 실험 2 · BCD → 이진수 변환 (bcd_conv)

① 목적

십의 자리와 일의 자리를 각각 4비트 BCD(0~9)로 받아 하나의 이진수(0~99)로 바꾼다. 각 자리가 0~9를 벗어나면 valid를 0으로 내려 잘못된 입력임을 알린다.

② 이론 · 설계 계산

BCD란. 사람이 읽는 10진수의 각 자리를 4비트씩 따로 적는 방식이다. 예를 들어 42는 BCD로 0100 0010이지만, 이진수로는 010 1010이다. 두 표기는 같은 수를 다르게 적은 것이다. 계산기 화면(자리별 숫자)과 컴퓨터 내부(이진수) 사이를 잇는 다리가 이 회로다.

변환식. 자리값을 곱해 더하면 된다 [1].

$$N = 10\,T + O,\qquad 0 \le T, O \le 9 \;\Rightarrow\; 0 \le N \le 99 < 2^7 = 128$$

그래서 결과는 7비트면 충분하다. 하드웨어에서 \(\times 10\)은 시프트와 덧셈으로 만들 수 있다. \(10T = 8T + 2T = (T \ll 3) + (T \ll 1)\)이다. 예를 들어 \(T=4\)이면 \(32 + 8 = 40\)이다.

유효성. 4비트는 0~15를 담을 수 있지만 BCD 한 자리는 0~9만 허용한다.

$$\text{valid} = (T \le 9) \land (O \le 9)$$

입력 조합 256개 중 유효한 것은 \(10 \times 10 = 100\)개, 무효는 156개다. 무효 입력일 때도 bin은 \(10T+O\)를 계산하지만 7비트만 남으므로 128로 나눈 나머지가 나온다. 예를 들어 \(T=O=15\)이면 \(165 \bmod 128 = 37\)이다. 이 값은 의미가 없으므로 valid와 함께 읽어야 한다.

3. 실험 3 · STM32_0 과제1 — 버튼으로 LED 간격 변경

① 목적

NUCLEO-G474RE의 사용자 버튼(PC13)을 누를 때마다 내장 LED(PA5)의 상태 변경 간격을 1 s → 2 s → 4 s → 8 s → 1 s 순서로 바꾼다. 버튼을 누르지 않아도 LED는 정해진 간격으로 계속 깜빡이고, 버튼을 누르고 있어도 간격은 한 번만 바뀌어야 한다.

② 이론 · 설계 계산

폴링 방식. FPGA는 회로가 항상 동시에 동작하지만, MCU는 CPU가 명령을 한 줄씩 실행한다. 메인 루프가 polling_routine()을 계속 호출하고, 함수는 호출될 때마다 "버튼이 눌렸나?"와 "시간이 됐나?"를 차례로 확인하고 바로 돌아온다. 우체통을 수시로 열어 보는 것과 같다. 함수 안에서 기다리지 않기 때문에(HAL_Delay 없음) 버튼 확인과 LED 시간 확인이 서로를 막지 않는다.

시간 재기. HAL_GetTick()은 1 ms마다 1씩 늘어나는 32비트 카운터 값을 돌려준다. HAL 기본 설정에서 이 증가 주기는 1 kHz이다 [2]. LED를 바꿀 때 시각 last_ms를 저장해 두고, 지금 시각과의 차이가 간격 이상이면 다시 바꾼다.

$$\Delta = (\text{now} - \text{last}) \bmod 2^{32} \;\ge\; \text{interval} \;\Rightarrow\; \text{LED 반전}$$

부호 없는 32비트 뺄셈은 자동으로 \(2^{32}\)로 나눈 나머지가 되므로, 카운터가 약 \(2^{32}\,\text{ms} \approx 49.7\)일 뒤 0으로 넘어가도 차이는 올바르게 계산된다. 이 성질은 ⑤에서 모의 실행으로 확인했다.

간격과 깜빡임 주기. 간격은 켜짐→꺼짐 한 번의 시간이다. 켜짐과 꺼짐을 합친 깜빡임 한 주기는 간격의 두 배다.

$$T_{\text{blink}} = 2\,t_{\text{interval}},\qquad t_{\text{interval}} \in \{1, 2, 4, 8\}\ \text{s} \;\Rightarrow\; T_{\text{blink}} \in \{2, 4, 8, 16\}\ \text{s}$$

간격 순환 규칙. 두 배로 늘리고, 8 s 다음에는 1 s로 돌아간다. 비교를 == 8000U가 아니라 >= 8000U로 써서, 값이 어떤 이유로 어긋나도 반드시 1 s로 돌아오게 했다.

한 번 누름 = 한 번 변경 (에지 검출). 버튼 값을 그대로 쓰면 누르고 있는 동안 계속 참이 되어 간격이 마구 바뀐다. 그래서 "지금은 눌림, 직전에는 안 눌림"인 순간만 인정한다. 매뉴얼 예제와 같이 이 보드의 버튼은 누르면 HIGH로 읽힌다.

$$\text{press} = (\text{current} = 1) \land (\text{previous} = 0) \land (\text{now} - \text{last\_press} \ge 200\ \text{ms})$$

마지막 조건은 채터링 대책이다. 버튼 접점은 눌리는 순간 수 ms 동안 붙었다 떨어지기를 반복할 수 있다. 200 ms 안에 다시 검출된 누름은 무시한다.

④ 핵심 코드

매뉴얼 제공 예제 1(1초 점멸)과 예제 2(버튼 에지 검출)를 한 함수에 합치고, 고정값 1000U를 변수 interval_ms로 바꿨다. ①은 이 변수를 바꾸고, ②는 이 변수를 읽는다.

void polling_routine(void)
{
    static uint32_t last_ms = 0;              // 마지막으로 LED를 바꾼 시각
    static uint32_t interval_ms = 1000U;      // 지금 간격 (처음은 1초)
    static GPIO_PinState previous = GPIO_PIN_RESET;  // 직전 버튼 상태
    static uint32_t last_press_ms = 0;        // 마지막으로 버튼을 인정한 시각

    uint32_t now_ms = HAL_GetTick();          // 지금 시각 (ms)
    GPIO_PinState current = HAL_GPIO_ReadPin(BUTTON_ece2_GPIO_Port, BUTTON_ece2_Pin);

    /* ① 버튼 확인: 방금 눌린 순간이면 간격을 다음 값으로 */
    if (current == GPIO_PIN_SET && previous == GPIO_PIN_RESET
        && now_ms - last_press_ms >= 200U)
    {
        last_press_ms = now_ms;
        if (interval_ms >= 8000U)
        {
            interval_ms = 1000U;              // 8초 다음은 1초로 돌아감
        }
        else
        {
            interval_ms = interval_ms * 2U;   // 1→2→4→8초
        }
    }
    previous = current;

    /* ② 시계 확인: 간격만큼 지났으면 LED 반전 */
    if (now_ms - last_ms >= interval_ms)
    {
        last_ms = now_ms;
        HAL_GPIO_TogglePin(LED_ece2_GPIO_Port, LED_ece2_Pin);
    }
}

⑤ 시뮬레이션 (호스트 모의 실행)

보드 없이 타이밍을 확인하려고, 위 polling_routine()을 저장소 파일에서 그대로 잘라 PC의 gcc로 컴파일했다. HAL_GetTick · HAL_GPIO_ReadPin · HAL_GPIO_TogglePin만 가짜 함수로 바꿨다. 가짜 시계는 1 ms씩 가고, 1 ms마다 함수를 3번 호출해 메인 루프가 빠르게 도는 상황을 흉내 냈다. 버튼 시나리오는 다음과 같다.

  • 10.05 s에 눌러 1.5 s 동안 유지 → 간격이 한 번만 바뀌어야 함
  • 30.05 s에 짧게 누름
  • 60.05 s에 40 ms 누르고 뗀 뒤, 3 ms · 7 ms 후 채터링처럼 접점이 두 번 더 붙음 → 한 번만 인정되어야 함
  • 100.05 s에 누름 → 8 s 다음은 1 s

예상과 다른 점 하나 (설계상 정상) — 표의 2.05 s×1은 100.05 s에 간격을 8 s에서 1 s로 줄이는 순간 생긴다. 마지막 변경(98 s) 뒤 이미 2.05 s가 지나 있었으므로 1 s 조건을 곧바로 만족해 LED가 누르는 즉시 한 번 바뀐다. 반대로 간격을 늘릴 때(예: 10.05 s)는 마지막 변경 시각부터 새 간격을 센다. 과제 조건(누를 때마다 간격 변경, 계속 깜빡임)은 모두 만족하므로 그대로 둔다. 보드에서 8 s → 1 s로 바꿀 때 LED가 바로 한 번 바뀌는 것이 정상임을 미리 알아 둔다.

4. 실험 4 · STM32_0 과제2 — 외부 LED로 동작시키기

① 목적

과제1과 똑같은 동작을 보드 밖에 꽂은 LED로 보여 준다. 프로그램이 핀 이름만 바꾸면 다른 장치를 같은 방식으로 다룰 수 있다는 것을 확인한다.

② 이론 · 설계 계산

배선. 매뉴얼대로 PB0 → 저항 → LED 긴 다리(+), LED 짧은 다리(−) → GND로 연결한다. PB0이 HIGH(3.3 V)가 되면 전류가 흘러 LED가 켜진다. 저항은 전류를 제한하는 수도꼭지 역할이다.

$$I = \frac{V_{\text{OH}} - V_F}{R} \approx \frac{3.3 - 2.0}{R} \;\Rightarrow\; R = 330\,\Omega: \;\approx 3.9\ \text{mA},\qquad R = 1\,\text{k}\Omega: \;\approx 1.3\ \text{mA}$$

\(V_F \approx 2.0\) V는 빨간 LED를 가정한 값이다. 실제 LED 종류에 따라 다르며, 어느 경우든 수 mA 수준이라 밝기만 달라진다. 매뉴얼 권장 범위(330 Ω~1 kΩ) 안에서 고른다.

코드 변경. 과제1 코드에서 LED를 바꾸는 한 줄의 포트 · 핀 이름만 PA5에서 PB0으로 바꾼다. HAL_GPIO_TogglePin은 출력 데이터 레지스터(ODR)의 현재 값을 읽어 반대로 설정하는 함수라 [2], 어느 GPIO 핀에든 같은 방식으로 동작한다. PB0은 수업 프로젝트에서 이미 출력(초기 LOW)으로 설정되어 있다.
